# DESIGN-SPEC v1 — 儿童离线游戏共享契约（第一批）

> 三个实现 agent 共享的唯一契约。凡与本文冲突以本文为准；本文未定者按 agent 最佳判断并在交付说明中记录。
> 视觉/音频节的数值为保守默认值，标注〔待校准〕处等 Agent R 调研结果回来后由主会话统一修订，届时以修订版为准（当前按默认值实现不会返工——默认值即保守安全值）。

## 0. 产品硬约束

- 对象：5-6 岁起步（难度第一档），预留 7-8 岁档参数；女孩向但不刻板。
- 载体：**单文件 HTML**（全部 CSS/JS/SVG/数据内嵌，零外部请求、零字体外链、零 http 引用）。笔记本（鼠标/触控板，Windows Chrome/Edge）+ 华为 MatePad（触摸，华为浏览器/Chrome）。
- 商业红线：无广告、无内购、无推送、无外链、无账号、无联网、无数据上传。
- 交互红线：失败零惩罚（失败即温和提示+重试）、无时间压力（第一档）、触摸目标 ≥64×64 CSS px 且间距 ≥16px、无频闪动画（不出现 >3 次/秒的对比闪烁）、动效 200-400ms ease。
- 文字红线：第一档零文字依赖——所有指令用"图标+动画示范+可选 TTS 语音"表达；界面文字仅家长面板内出现。

## 1. 通用技术规范

- 输入：统一用 Pointer Events（pointerdown/pointerup/pointermove），`touch-action:none` 于游戏容器，禁双指缩放；单击=pointerdown 触发（儿童按住不放也应响应，不要等 pointerup）。
- viewport：`<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`；布局双方向响应式（min-width 720 布局与窄屏 ≤800 布局都能玩）；`env(safe-area-inset-*)` 避让。
- 渲染：DOM/CSS + 内联 SVG 优先（合成层动效用 transform/opacity）；Canvas 仅厨房节奏的游戏区用。DPR 处理：canvas 按 `min(devicePixelRatio,2)`。
- 音频：仅 Web Audio 合成，无音频文件；`KIDS.audio` 封装（见 core.js）。首次 pointerdown 解锁 AudioContext。
- TTS：`KIDS.speak(text)`（speechSynthesis，zh-CN，语速 0.9）；设置可关。
- 性能目标：MatePad 上 60fps（对象少、动效简单，默认可达）。

## 2. 会话结构规范（每款必须实现）

1. **关卡→章节**：5 关=1 章节。每关过关→星星（1-3 星按表现）+ 即时庆祝动画（≤2 秒）。
2. **章节收尾仪式**：第 5 关完成后进入结算画面：小兔子盖印章动画 + 本章成果（星星总数）+ "明天见"预告（明日新内容图标预览，如"明天有弯弯的三通水管"）。
3. **内容日历**：关卡按天解锁，每日新关基数 6（首日）、12（第 2 天起封顶，`min(dayIndex,2)×6`）；旧关可无限重玩。当日新关全部完成 → "今天的新关卡玩完啦"收尾画面（小兔子挥手）+ 明日预告。**不锁死**：收尾画面可关闭继续重玩旧关。内容无限的游戏（生成关）`limit(Infinity)`。
4. **休息提示（软）**：当日累计游玩 13 分钟 → 小兔子打哈欠画面"我的眼睛要休息啦，明天见"（TTS 同步）；点击关闭可继续，25 分钟时再提示一次。不强制锁。
5. **家长面板**：右上角"家长"小图标（低调）→ 家长门（**两位数加法随机题**——10 以内加法是幼儿园大班常规内容，挡不住目标儿童；答案输入用数字键盘）→ 面板内容：总进度/每日游玩分钟/最后游玩日期/声音与 TTS 开关/**今日多玩关数手动输入框（0-30，设置语义替换旧值，家长在场时灵活放宽）**/存档导出（下载 JSON）/存档导入/重置。
6. **首次进入**：无标题菜单直接进教学关（第 1 关即教学关：高亮+幽灵手指动画示范一次操作，然后等孩子模仿）。

## 4. 公共内核 core.js（每个游戏原样内嵌）

API 概要（实现见 design/core.js，游戏页 `<script>` 内联其全文）：

- `KIDS.init({game, title})` — 初始化（必须在其它调用前）
- `KIDS.audio.unlock()` / `.sfx(name)`（ok/fail/click/pop/win/coin）/ `.note(freq,dur,when,vol)` 马林巴音色
- `KIDS.speak(text)` — TTS，设置关闭时静默
- `KIDS.voice.play(key, text)` — 语音优先播内嵌 clip（key），缺失/失败回退 TTS（text）；`KIDS.voice.queue(parts)` — 拼接句顺序播报（段间 0.15s，缺 clip 放弃拼接整句 TTS 兜底）；`KIDS.voice.say(text)` — 强制 TTS。clip 注入见 voice/inject_clips.py（build 时内嵌 base64 mp3，edge 晓晓 zh-CN-XiaoxiaoNeural -8%/+18Hz）。游戏内语音只在前 3 关播（sayP 包装），core 低频语音（章末/日末/休息）不受限。
- `KIDS.calendar.limit(total)` — 今日解锁的关卡总数（每天 +3）；`KIDS.calendar.isNew(flatIdx, total)` — flatIdx 处的关是否今日已解锁；`KIDS.calendar.dayDone(keysFlat)` — 今日新关是否全部完成（keysFlat=全部关卡 key 的扁平数组）
- `KIDS.level.pass(ch, lv, stars, chapterLevels)` — 写档并返回 `{chapterDone}` 供游戏触发章节仪式（dayDone 用 calendar.dayDone 另查）
- `KIDS.session.start()` — 开始计时（内部每 30s 记分钟、到阈值回调 `onRestTip`）
- `KIDS.ui.celebrate(stars)` — 过关庆祝覆盖层（类名 `.k-celebrate`）；`KIDS.ui.chapterEnd(info)` — 章节结算（`.k-chapterend`）；`KIDS.ui.dayEnd(info)` — 今日完成（`.k-dayend`）；`KIDS.ui.restTip()` — 休息提示（`.k-resttip`）。类名供验收脚本断言。
- `KIDS.parent.init()` — 家长面板（含家长门）
- `KIDS.assets.rabbit(pose)` — 小兔子 SVG 字符串（pose: normal/happy/sleepy/wave）

游戏自建部分只做玩法；上述仪式/面板/存档全部走 core。

## 5. 管道小兔子（pipe-rabbit）设计

**玩法**：网格棋盘，起点水龙头 → 终点花盆。点按管道块旋转 90°（顺时针），全部接通后自动放水（水流动画沿路径）→ 花盆开花 → 小兔子跳出来庆祝。5 关=一章节"一座花园"。

**管件类型**（第一档）：`I`（直管，两向）、`L`（弯头）、`T`（三通，第一档章节 3 后引入）、`S`（起点，固定不可转）、`F`（花盆终点，固定）。格子 4×4（章节 1-2）→ 5×4（章节 3+）。障碍格（石头，无管道）章节 2 起。

**关卡数据**（内嵌 JSON）：
```js
const LEVELS = [
 { ch: 1, title: '小花园', levels: [
   { grid: [4,4],
     start: {x:0, y:2},            // 水从起点向右流出
     goals: [{x:3, y:2}],
     cells: [ {x:1,y:2,t:'I'}, {x:2,y:2,t:'L'} ],   // t=管型；初始 rot 由程序随机
     rocks: [] }
 ]}
];
```

**有解性保证（必须）**：关卡由"解路径反向构造"——先在编辑数据里写好正确连通布局（cells 即为解），程序加载时对每个可转管件随机初始 rot∈{0,1,2,3}。因此每关必然有解（转回解即可）。教学关（1-0）初始 rot=解的 rot（开局即通，配合放水演示）。

**通关判定**：从起点做 BFS/DFS 沿管口连通遍历，水流到达全部花盆即过关（有多出口的管件按连通性自然处理；不要求"无漏水"——第一档只要求连到花盆）。

**星级**：点击次数 ≤ 解所需最小旋转数的 1.2 倍=3 星；≤2 倍=2 星；否则 1 星（永不 0 星、永不失败——乱点只是还没通）。

**反馈**：每次旋转=轻微咔哒+管件缓动；连通瞬间=水流声（合成白噪滤波）+花盆开花；过关=小兔子 happy + 上行琶音。

**`?verify=1` 自检接口**：
- 对全部关卡：以解 rot 为目标做连通性验证（解状态必须 PASS）；
- 用 BFS 求解器对"随机初始 rot"实际求解（限定步数 ≤200），输出每关 `ch-lv: solvable(旋转步数)`；
- 结果写入 `#verify-result`（JSON 文本节点）与 `document.title`（"VERIFY PASS n/n" 或 "VERIFY FAIL"）。

**playwright 验收协议**：主会话脚本读 `#verify-result`，并取第 1、2 关的求解旋转序列逐格模拟 pointerdown 点击 → 断言出现过关庆祝层（`.k-celebrate` 存在）。

## 6. 数字小卖部（shop-math）设计

**玩法**：孩子的水果店。小动物顾客进场（门口排队可视）→ 头顶气泡显示需求（图标×数量，如 🍎×3 🍌×2，配 TTS"我要三个苹果和两根香蕉"）→ 孩子点货架上的苹果/香蕉/梨/橙子放入篮子（篮中计数实时显示，可点篮中商品放回）→ 点大按钮"结账"（购物车图标）→ 正确：小动物付币动画+开心离开+货架记录一颗果；错误：小兔子温和提示"再数一数呀"（气泡闪烁数量、TTS 重报需求），篮子不清空可继续调整。5 位客人=1 章节，收尾=小店打烊（卷帘动画）+今日收入（果子数）+明日预告（明天小象要来买橙子哦）。

**订单生成**（参数化，内嵌基础顾客脚本+程序生成）：
- 第一档：每种商品数量 1-5，商品种数 1-2，"结账"只验证总数对应正确（点数+和≤5 的加法）。
- 预留第二档（7-8 岁）：价格标签（每件 1-3 元）→ 总价加法 → 用 1/2/5 元硬币付款/找零（参数 `mode:'price'`，本期可只留接口不实现 UI）。
- 数据：`CUSTOMERS = [{who:'cat', items:[{k:'apple',n:3},{k:'banana',n:2}], mode:'count'}]` × 20 位（4 章）。

**防挫败**：无倒计时；错误上限 3 次后高亮正确货架并演示放入一个（支架）；任何时刻可点"小兔子帮忙"按钮看一次演示。

**`?verify=1`**：遍历全部订单：模拟自动装篮（正确数量）→ 结账 → 断言离开动画状态；再测错误路径（装错数量→结账→断言进入提示态而非扣分）。结果写 `#verify-result` + title。

**playwright 验收**：模拟完成 2 位客人的完整真实点击流（点货架 N 次→结账→断言顾客离场+进度果+1）。

## 7. 厨房节奏（kitchen-rhythm）设计

**玩法**：食材随旋律从右侧传送带滑向左侧判定圈，到达判定圈时点击"切"→ 食材两半飞出+对应音符响起（每命中一个音符，旋律前进一格——**玩家的命中就是旋律本身**，这是核心设计：打对了自然成曲）。漏掉=食材掉到地上被小猫叼走（无失败、无扣分、曲目继续）。一曲终了=装盘结算（切了多少、小猫收了多少，都是正反馈）+ 星级按命中率（≥60%=1 星起步，永不 0 星）。另设"自由琴键"模式（8 键马林巴随便敲，无目标）。

**曲目数据**（内嵌 JSON，时间为拍数）：
```js
SONGS = [{ title:'小星星', bpm: 88, beats: 32,
  notes: [ {t:0, kind:'carrot'}, {t:1, kind:'tomato'}, {t:2.5, kind:'egg'} ... ],
  melody: [523.25, 523.25, 587.33, 587.33, 659.25, 659.25, 587.33, 0, ...]  // 频率数组,0=休止
}]
```
第一档：3 曲（小星星/两只老虎/欢乐颂片段），BPM 80-95，note 密度 ≤0.8 个/拍，只用 3 种食材（胡萝卜/番茄/鸡蛋，颜色形状差异大）。

**判定**：判定窗口 ±250ms（宽松，儿童向）；命中音=该拍 melody 频率马林巴音；连击 5 个以上小兔子跳舞（视觉糖）。

**音频时钟**：以 `audioContext.currentTime` 为主时钟驱动（不用 setInterval），保证音画同步；BGM 无常驻背景音乐（旋律由玩家命中产生，未命中时该音符静音——旋律完整与否本身就是反馈）。

**`?verify=1`**：全曲目数据校验（时间严格递增、无 <0.5 拍间隔冲突、melody 长度≥note 数）+ auto-hit 模式跑完第 1 曲（程序自动在判定时刻命中）→ 断言结算层出现。结果写 `#verify-result` + title。

**playwright 验收**：`?verify=1&auto=1` 跑完一曲断言结算（`.k-song-end`）；另在手动模式注入 5 次随机时刻点击断言无异常。

## 8. 视觉规范（已按 Agent R 实证校准 2026-09-05，档案 research/agent-r-kids-ux.md）

- 底色：奶油暖白 `#FBF3E4`；纸面/卡片 `#FFF9EE`；文字暖深棕 `#4A3B2E`（正文仅家长面板）。
- 主色：暖橙 `#E8975A`（按钮/高亮）；辅助柔绿 `#8FBF7F`（正确/成功）；错误/提示用灰蓝 `#8A9BAE`（**不用大红**，错误色取低饱和）；点缀粉 `#F2B8C6`（兔子腮红/花）。
- 色彩实证依据（4-7 岁眼动研究）：明快、中等偏亮、保留相当饱和度的暖色最优——**既不要最高饱和浓彩，也不要淡到发灰的粉彩**；前景与背景中等偏强对比（前景元素必须明显跳出奶油底）。7-8 岁上段忌"太 baby"，配色不过分幼态。
- 状态编码铁律：正确/错误等状态**不得仅靠红绿区分**，必须形状冗余（勾/叉/图标/动效）——受众红绿色弱男童约 8%（实证）。
- 交互物区分：可点/可拖元素用白描边、投影或微动效三选一与背景区分；非交互背景降饱和。
- 饱和度整体中低（HSL S≤60%）；无渐变堆砌、无多色并置超 3 色/屏。
- 图形：圆润（大圆角、无尖角元素）、描边风格统一（2.5px 暖棕描边），角色占屏大（≥15% 屏高）。
- 进度可视化：星星（过关）、果子（章节）、路线图（章节间小路+旗子）——具象三选一，不用百分比/抽象分数（推断+行业共识）。
- 触摸目标（NN/g 一手研究校准）：**主交互目标 ≥96×96 CSS px（约 2cm @平板 DPR2）**；普通元素底线 64×64 不再放宽；间距 ≥16px；主行动按钮置于拇指区（下半屏）。
- 闪烁红线（WCAG 2.3.1 硬规范）：任一 1 秒周期 ≤3 次闪、无饱和红闪；星星闪光/连击特效小面积慢频率。

## 9. 音频规范（已按 Agent R 校准）

- 音色：马林巴风=正弦基频+2.9 倍泛音（-14dB）+指数衰减包络（attack 5ms，decay 按 dur）——与 Web Audio 马林巴标准合成模式（sine+约 4 倍频非谐泛音+快 attack 指数衰减）同构。
- 成功音：短促上行大音程（大三度 C5→E5，明亮音色）——上行=成功业界共识；失败音：低闷单音（G3, 0.15s，音量 50%）——"柔和下行/闷音"，**禁刺耳 buzz/警报声**；按钮咔哒：短噪声脉冲高通滤波。
- BGM：无常驻（管道/小卖部——音乐复杂度与玩法复杂度成反比的极端形式：解谜时无旋律干扰）；节奏游戏旋律由玩家命中产生（大调，BPM 80-95）。若后续加 BGM：大调 80-100 BPM、简单清晰旋律、软音色。
- 混音层级：语音 > 音效 > BGM；TTS 朗读时无 BGM 需避让（本批天然满足）。
- 反馈延迟：点按音画反馈 <100ms（听觉感知窗 20-70ms/视觉 30-85ms，儿童确认线 150ms）——本地实现天然满足，禁止在点击处理器里做耗时同步计算。
- 整体音量默认 0.6，家长面板可调 0-1；全程静音可玩（声音不承担唯一信息通道）。

## 10. 引导规范（已按 Agent R 校准）

- 教学关走 **"看-帮-独"三步**（渐进释放责任，教育界共识）：
  1. **看（I do）**：首次进入教学关，自动演示一遍完整解法流程（动画+音效，TTS 只做简短说明）——管道=演示一次连通放水；小卖部=演示最小订单装篮+结账；节奏=前 4 个音符自动命中。
  2. **帮（We do）**：孩子首次操作带幽灵手指高亮协助（半透明白色手指 SVG 移动到目标+按下波纹，示范 1 次，5 秒无操作再示范 1 次）。
  3. **独（You do）**：完成第一步立即强化反馈，后续不再示范，放手独立完成。
- 零文字教学为主（show don't tell）；必须的文字=图标+单个描述词；禁用抽象图标（home/软盘类），Play/箭头类可用。
- 需求/指令显示：图标+数量（数字配点数圆点），TTS 同步朗读（中文，语速 0.9≈成人速 7-8 成，句间留白）；指令可点击重播。
- TTS 定位：**教学优先靠动画+音效，语音只做简短鼓励**（系统 TTS 表现力有限，避免机器味担任主角）；表扬语具体化（"你把管子都对上了！"而非空泛"好棒"）。
- 错误反馈：绝不出现大红叉/哭脸，也**不只给错误标记就翻篇**——给再试机会（篮子不清空可继续）、3 次错误后高亮正确货架演示支架；失败动画克制有趣（防孩子"故意输着看动画"）。
- 无操作 20 秒：轻声 TTS 提示一次当前目标（可关）。
